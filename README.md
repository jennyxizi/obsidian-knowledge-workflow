# Obsidian 知识库工作流

这是一个 Codex 技能，适合从零搭建 Obsidian 知识库、从历史对话中提炼长期知识，以及优化已有库。它先帮你确定知识库要解决的实际问题，再决定需要收集哪些信息、建立哪些页面。

## 怎么用

在 Codex 中调用这个技能，或打开本仓库并让 Codex 读取 [SKILL.md](SKILL.md)。告诉它你想用知识库完成什么，以及你已有的笔记或历史资料。例如：

> 我想用 Obsidian 建一个能帮助 AI 理解我和我业务的知识库。我希望它能根据上次反馈帮我改活动流程，也能根据我的经验帮我准备客户面谈。请先帮我确认用途和最小结构，等我确认后再搭建。

有现成的库时，也可以把任务限定在一部分：

> 我已经有一个 Obsidian 库。请把这些历史对话提炼成最终结论并合并进现有笔记。项目状态按时间核对，重要决策保留理由和重评条件。

## 工作流程

1. 确认知识库的用途，用两三个实际任务描述它怎样才算有用。
2. 收集与用途有关的背景和现有资料。
3. 确认最小结构后搭建，目录按实际需要决定。
4. 从对话和资料中提炼长期有用的最终结论，合并进对应笔记。
5. 用真实任务试跑，再按需要补充链接、模板、项目总览或周复盘。

如果资料分散在其他 AI 里，可以把[历史对话提取提示词](references/history-extraction-prompt.md)中的用途和任务填好，再复制过去。把提取结果带回 Codex，即可核对并整理进知识库。

想借鉴 Obsidian CEO Steph Ango 的做法，可以查阅[方法指南](references/steph-ango.md)。里面有常青笔记、内部链接、Bases 和每周回顾各自适用的场景。
