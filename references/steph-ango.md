# 借鉴 Steph Ango 的 Obsidian 用法

按用户遇到的问题采用下列做法。他的个人习惯适合作为参考，具体布局由用户用途决定。

| 使用问题 | 他的做法与可采用的调整 |
| --- | --- |
| 同一条知识属于多个主题 | 他主要通过链接、反向链接和分类属性找笔记。保留用户已有布局，从最常使用的项目或主题页链接到相关知识。 |
| 项目经验只能在原项目里找到 | 他用简明、可记忆的标题表达常青笔记中的观点。比如把某次项目取舍沉淀为「技术投入应跟随已验证的业务需求」，正文只写判断、理由和重评条件，再链接实际应用。只有值得跨项目复用的判断才独立成页。 |
| 项目表与正文经常不一致 | 他用模板、可复用属性和 Bases 组织笔记。可从类型、状态和信息更新日期起步，让汇总直接读取项目页。状态要有依据，信息更新日期代表内容的时点。 |
| 记录很多，结论很少 | 他随手捕捉碎片，分阶段回顾，并按周维护待办。可以简化为每周一页，列三件要事，回顾哪些结论需要写回。 |
| AI 提炼时替用户作判断 | 他强调亲自理解，也提到自己喜欢手动回顾。AI 可以提炼、查重和建议链接。用户明确认可的判断才作为其个人口径保存。 |

原始分享：[他的 Obsidian 用法](https://stephango.com/vault)、[常青笔记](https://stephango.com/evergreen-notes)、[每周待办](https://stephango.com/todos)、[亲自理解](https://stephango.com/understand)。
